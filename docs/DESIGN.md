## Emprint Design System

## Radius Philosophy

Use restrained radius values.

Avoid overly rounded consumer-style UI.

Recommended:
- Small: 4px
- Medium: 6px
- Large: 8px

The interface should feel:
- precise
- editorial
- engineered

---

# Spacing Philosophy

Spacing should support:
- density
- readability
- scanning efficiency

Avoid:
- oversized padding
- excessive whitespace

The product is closer to:
- IDEs
- editors
- workspaces

than marketing websites.

---

# Shadows

Shadows should remain subtle.

Avoid:
- floating card aesthetics
- dramatic neumorphism
- glossy depth

Preferred:
- layered darkness
- soft separation
- low contrast elevation

---

# Borders

Borders are important.

Use:
- subtle separators
- muted dividers
- quiet panel distinction

The interface should feel structured and archival.

---

# Typography Scale

Typography should emphasize:
- hierarchy
- readability
- editorial clarity

Avoid:
- oversized headings
- playful typography
- excessive font variation

Recommended direction:
- UI → Inter / Geist
- Code → JetBrains Mono
- Editorial accents → IBM Plex Sans

---

# Iconography

Icons should feel:
- technical
- restrained
- minimal

Avoid:
- cartoon styling
- thick playful icons
- heavy illustration aesthetics

Preferred inspiration:
- VSCode
- Linear
- Raycast
- Obsidian

---

# Color System

## Base

Prefer:
- charcoal
- graphite
- muted brown
- ash gray

Avoid:
- pure black
- bright white
- saturated gradients

---

## Accent

Accent colors should resemble:
- embers
- terminal cursors
- warm copper
- dim firelight

Accent usage should remain sparse and meaningful.

---

# Component Identity

Components should feel:
- modular
- lightweight
- intentional
- keyboard-friendly

Avoid oversized cards and excessive decorative surfaces.

---

# Density Rules

The application should support:
- compact mode
- dense workspace layouts
- multi-panel workflows

The user should feel capable of:
- managing many documents
- navigating quickly
- remaining focused for hours

---

## Emprint Interaction Philosophy

## Core UX Direction

The application should feel:
- responsive where it matters (editing, saves, navigation)
- calm
- intentional
- clear (low mystery, filesystem-transparent)

Every interaction should reinforce focus. Favor **deliberate** pacing over dopamine-driven “instant everything”; see [`PRODUCT.md` — Part 1](PRODUCT.md#part-1--philosophy).

---

# Keyboard First

Keyboard workflows are extremely important.

The product should eventually support:
- command palette
- global shortcuts
- editor shortcuts
- navigation shortcuts
- quick switching

Mouse dependency should be minimized where appropriate.

---

# Motion Design

Animations should feel:
- subtle
- quiet
- mature

Preferred:
- opacity fades
- gentle transitions
- restrained movement

Avoid:
- bounce animations
- playful elasticity
- exaggerated movement

---

# Hover States

Hover states should communicate:
- clarity
- affordance
- precision

Avoid:
- excessive glow
- dramatic motion
- noisy highlights

---

# Command Palette

The command palette should feel like:
- a runtime console
- a workspace controller
- a universal interface layer

Inspired by:
- Raycast
- VSCode
- Cursor
- Linear

---

# Context Menus

Context menus should feel:
- lightweight
- fast
- information dense

Avoid oversized mobile-style context sheets.

---

# Editing Experience

The editing experience should support:
- long-form thinking
- iterative refinement
- exploration
- versioned creativity

The interface should never pressure the user into rapid content production.

---

# AI Interaction Philosophy

AI should feel:
- quiet
- contextual
- assistive
- archival

NOT:
- noisy
- intrusive
- aggressively automated

The AI should feel like:
- an archivist
- a research companion
- a thoughtful collaborator

## Emprint Layout Philosophy

## Workspace Structure

The interface should feel like a workspace, not a feed.

Preferred structure:

- Sidebar
- Explorer
- Main editor/viewer
- Optional secondary panels
- Command overlays

---

# Sidebar Philosophy

The sidebar represents:
- accumulated work
- historical structure
- layered thinking

Inspired by:
- archive drawers
- library indexes
- git trees
- IDE explorers

The sidebar should remain:
- stable
- dense
- navigable by keyboard

---

# Editor Area

The editor is the emotional center of the product.

Prioritize:
- focus
- readability
- uninterrupted writing
- uninterrupted coding

Avoid:
- excessive overlays
- social UI
- noisy widgets

---

# Multi-Panel Support

The layout should eventually support:
- split editors
- preview panels
- git history
- AI assistant panels
- explorer trees

The architecture should anticipate future IDE-style layouts.

---

# Width Philosophy

Do not over-constrain the editor width.

Users should be able to:
- write long-form content
- inspect code comfortably
- manage dense workspaces

---

# Responsive Philosophy

Desktop-first design.

The primary target environment is:
- large monitors
- developer workstations
- creative workspaces

Avoid excessive mobile-first compromises.

---

# Layout Mood

The workspace should feel:
- calm
- grounded
- intentional
- archival
- immersive

Like entering a personal archive of thought.
